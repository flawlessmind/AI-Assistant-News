# Альфа-Будущее 2026 · Новостная аналитика для бизнеса

Приложение кейса №3: компания и роль → релевантное событие → банковские
источники → условная персонализированная интерпретация → уточнение и проверяемый шаг.
Приёмка актуальных исходников: **24 октября 2026**. Короткий вход — [START_HERE_RU.md](START_HERE_RU.md),
результаты и ограничения — [статус поставки](docs/RELEASE_STATUS.md).

## Запуск с нуля

Нужен Python **3.12** с SQLite FTS5; закреплённая версия **3.12.14**.
HTTP обслуживает Waitress 3.0.2; локальный смысловой поиск использует ONNX Runtime, NumPy и Tokenizers. Полный список
версий — `requirements.lock.txt`. Node, npm, MCP и повторный OCR для запуска не нужны.
Архив распаковать в отдельную папку и выполнять команды из её корня:

```powershell
python -X utf8 scripts/start.py --port 8002
```

На Windows можно также открыть `START_WINDOWS.cmd`. Скрипт создаёт `.venv`, устанавливает
закреплённые зависимости, проверяет веса/индекс и запускает сервер. Интернет нужен для
первой установки пакетов. В ZIP веса уже включены; в исходной копии без весов скрипт
восстанавливает публичную закреплённую модель с проверкой размера и SHA-256.

Открыть [http://127.0.0.1:8002](http://127.0.0.1:8002). Терминал оставлять открытым;
остановка — Ctrl+C. Если порт занят, использовать `--port 8003` и соответствующий адрес.
На Windows второй сервер на том же порту отклоняется. После изменения кода перезапустить
сервер; обновления вкладки недостаточно. Существующую `.env` и папку `var` сохранять.

После подготовки окружения пять профилей, 50 настоящих новостей из двух издателей,
OCR-страницы и смысловой поиск доступны без ключа и сети. Ответ модели не подменяется
заготовкой. `var` создаётся при запуске:
новости, вызовы, результаты, кеш и trace хранятся в `var/service.sqlite`.

```powershell
docker compose up --build
```

Docker публикует только `127.0.0.1:8000`, запускает процесс без root и сохраняет состояние
в томе `alfa-runtime`. `.env` не копируется в образ; Compose передаёт выбранные настройки
из окружения. Для другого порта задать `ALFA_HTTP_PORT`, например 18080. Не удалять том
для сброса лимита. Фактические проверки Docker приведены в текущем статусе. Версии закреплены в `.python-version`,
`runtime.lock.json`, Dockerfile и `requirements.lock.txt`. `requirements-ocr.txt` нужен
только для повторного извлечения PDF.

При SIGTERM/SIGINT новые этапы анализа прекращаются до ожидания HTTP-запросов.
Завершается текущий вызов, затем сохраняется ошибка прерванного задания без нового review.
Grace 210 секунд покрывает допустимый timeout текущего этапа до 180 секунд и завершение.
Аварийный SIGKILL не позволяет закончить сохранение: после restart исход вызова отмечается
неопределённым, расход не обнуляется и автоматической повторной отправки нет.

Подготовить окружение и проверить данные без запуска сервера:

```powershell
python -X utf8 scripts/start.py --check
.\.venv\Scripts\python.exe -X utf8 -m alfa_app doctor
```

`doctor` проверяет локальную готовность, не расходует LLM и не подтверждает доступность шлюза.

## Путь пользователя

1. Выбрать U_1595 и финансового директора. Через «Обзор бизнеса» открыть постоянный вход
   в новостную аналитику; выбранная компания сохраняется.
2. Открыть событие, прочитать причины релевантности. Факт новости, позиция банка и вывод
   модели разделены; дата источника и дата анализа показаны отдельно.
   В строке поиска можно написать «В магазинах изменились ценники на повседневные покупки»:
   сервер найдёт тематически близкую новость, даже если этих слов нет в заголовке.
3. Раскрыть доказательства, физическую страницу OCR, PDF и этапы проверки. Дословная
   цитата подтверждает наличие текста, но не автоматически истинность любого вывода.
4. Задать «Каких данных не хватает для полного вывода?». Детерминированный ответ
   `answer_origin=rules` не вызывает модель и соответствует отрасли/роли.
5. Найти источники по своему вопросу. При разрешённой генерации отдельное пояснение
   отвечает на вопрос с доказательствами, не заставляя повторять всю карточку.
6. Переключить U_83932 и руководителя: карточка сбрасывается, причины, приоритеты и
   необходимые данные меняются. При слабой связи показывается честная остановка.
7. С настроенным ключом запросить инсайт. Во время ожидания источники остаются видны,
   виден реальный этап задания. Дубликаты объединяются; после перезагрузки открыть ту же
   компанию, роль и новость — браузер продолжит чтение задания без новой генерации.
8. У готового вывода оставить оценку и необязательный комментарий. Отзыв сохраняется в
   локальной БД и доступен команде через агрегаты `/api/metrics`; это не вызов модели.

Кеш — ранее проверенный ответ с датой анализа. Профиль, компания, роль, задача, вопрос,
дата, редакция новости, индекс, модель и загруженная логика участвуют в fingerprint.
Прежние одобрения после изменения контекста отзываются; старый процесс требует перезапуска.
В чистой поставке нет runtime-кеша. Скриншоты и исторический результат 21.10 не являются
новой генерацией текущей версии.

## Ключ команды или экспертов

Существующую `.env` сохранить. Если её ещё нет:

```powershell
if (-not (Test-Path -LiteralPath '.env')) { Copy-Item -LiteralPath '.env.example' -Destination '.env' }
```

Локально заполнить `ALFA_LLM_API_KEY`, выбрать модель, включить `ALFA_ALLOW_LIVE_LLM=true`
и перезапустить сервер. Не передавать ключ через чат или браузер. Разрешены ровно два Base URL:

- `https://changellenge.up.railway.app/v1` — основной;
- `https://api.alfahack-gateway26.ru/v1` — альтернативный из предоставленного уточнения организаторов.

Один ключ и общий бюджет для обоих адресов. Произвольные URL и авторизованные редиректы
запрещены. Информация ключа запрашивается только у документированного основного
`https://changellenge.up.railway.app/key/info`; аналогичный endpoint запасного не предполагается.

Ровно шесть генеративных model ID:

```text
google/gemma-4-26b-a4b-it
z-ai/glm-5.3-flash
qwen/qwen3.6-35b-a3b
deepseek/deepseek-v4.1-flash
qwen/qwen3-vl-30b-a3b-instruct
moonshotai/kimi-k2.6
```

По умолчанию `ALFA_LLM_MODEL=deepseek/deepseek-v4.1-flash` готовит ответ, а
`ALFA_LLM_REVIEW_MODEL=google/gemma-4-26b-a4b-it` проверяет его отдельным запросом.
Обе модели входят в приведённый список и используют тот же шлюз, ключ и общий бюджет.
Это явная настройка этапов; автоматического переключения на сторонний сервис нет.
Для проверки той же моделью задать оба параметра одинаковыми. Смена любого из них
отзывает актуальность прежних одобрений; полный черновик может пройти новую проверку.

Если черновик оборван по длине либо содержит только рассуждения, приложение один раз
автоматически создаёт новый ответ через `ALFA_LLM_RECOVERY_MODEL` (по умолчанию Gemma).
Задание компактнее: до двух полных банковских страниц с исходными цитатами и оговорками;
оборванный текст не используется. Новый ответ проходит те же проверки и отдельный review.
Повтор расходует общий лимит ключа; ошибки ключа, бюджета и формата без обрыва повтор
не запускают. Второй обрыв завершает задание понятным сообщением и сохраняет источники.

Chat Completions через стандартный HTTP-клиент; инструменты, streaming, JSON mode/schema
и управление thinking не предполагаются. JSON проверяется локально. Усечённый ответ
не восстанавливается и не публикуется. Draft/review ограничены отдельно (8192/6144),
timeout 120 секунд. Самопроверка модели дополняет локальные проверки и не доказывает истинность.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m alfa_app.llm probe
```

Это проверка конфигурации без сети и расходов. `probe --live` отдельно выполняет один
генеративный запрос и чтение key/info; для обычного запуска и проверки источников не нужен.

Официальный бюджет **500 ₽ в день на ключ команды**, сброс **03:00 Europe/Moscow**.
Внутренний предел числа запросов по умолчанию отключён: `ALFA_MAX_CALLS_PER_PERIOD=0`.
При необходимости владелец может задать положительное число как дополнительный предел.
Для пробной новой установки можно начать с `ALFA_MAX_CALLS_PER_PERIOD=10`: это предел
числа попыток, не рублей. При двух раундах один анализ имеет не более пяти физических
вызовов, включая review и единственный recovery. На существующей установке сначала
посмотреть physical_attempts в `/api/metrics`: значение cap ниже уже учтённого расхода
сразу остановит новые вызовы до следующего периода. По умолчанию остаётся 0; рабочая
`.env` аудитом не меняется. Кеш не расходует cap, все модели делят один счётчик.
Журнал фактических попыток общий для всех моделей и обоих адресов и сохраняется без
обнуления; число попыток не эквивалентно 500 ₽. Другие установки расходуют тот же
официальный бюджет. Смена адреса/модели не снимает блокировку. Ошибки ключа и бюджета не
повторяются. После тайм-аута, сетевого обрыва, HTTP 408/429/5xx автоматического
повтора POST нет: шлюз уже мог обработать и оплатить запрос. Пользователь видит
предупреждение перед ручной новой попыткой. Каждая фактическая отправка учитывается
в своём периоде. Стоимость токенов и единицы баланса неизвестны.

Можно запустить анализ одной статьи и сразу перейти к другой: задания продолжаются
в фоне, по два одновременно. Всего допускается 16 ожидающих и выполняющихся заданий
(`ALFA_MAX_ACTIVE_JOBS`); одинаковое активное задание объединяется до проверки ёмкости.
Заполненная очередь возвращает HTTP 503, история сохраняется.
Результат и последняя ошибка сохраняются отдельно для каждой статьи. Кнопка
«Перегенерировать» запрашивает новый черновик и новую проверку; прежний ответ не
подставляется. Повторная отправка той же попытки не создаёт платный дубль.
Отказ проверки цитат или выводов показан понятным текстом и отличается от ошибки сети,
ключа или бюджета. Проверки обоснованности и конечные границы ответа модели сохраняются.
Текущий протокол: [целостность URL, параметры API и очередь](docs/SOURCE_INTEGRITY_AUDIT_2026-10-24.md).
Предыдущий [аудит поиска, метаданных и остановки](docs/FULL_AUDIT_2026-10-24.md) сохранён.
Предыдущая [проверка попыток и HTTP](docs/STABILITY_AUDIT_2026-10-24.md) сохранена.
Предыдущие [исправления P1–P3](docs/CONFIRMED_FIXES_2026-10-23.md) сохранены.
Вопросы одной статьи имеют отдельные задания с полным контекстом. После перезагрузки
они доступны по кнопкам с текстом вопроса; режим источников не подменяется ответом LLM.

## Данные и обновление

В наборе U_1595 — розничная торговля одеждой (47.71), U_83932 — жилищное строительство
(41.20.1), U_87 — производство металлоконструкций (25.11), U_768 — грузовые перевозки
(49.41.1), U_84 — оптовая торговля (46.90). Профили производные от предоставленных CSV,
с обезличенными идентификаторами, без вымышленных названий. Целевая аудитория кейса — крупный
бизнес с годовой выручкой свыше 15 млрд рублей; единицы и год CSV не подтверждены, поэтому
принадлежность этих компаний сегменту условна. Продуктовый маркер кредита не устанавливает
текущую задолженность; FTS не доказывает импорт/валюту; регистрация не равна географии продаж.
Группа и связь через физлицо не доказывают контроль. Валюта/период PAY_AMT неизвестны.
Для персонализации используются отрасли внешних платёжных контрагентов по числу уникальных
компаний, с отдельным учётом отсутствующих и неоднозначных профилей. Это не доли расходов
или продаж; направление платежа не устанавливает назначение. Происхождение и SHA-256
CSV зафиксированы в `data/profiles_provenance.json`. Пересборка: `scripts/build_profiles.py --help`.
Самопереводы выделены отдельно от внешних связей; отсутствующий профиль контрагента обозначен.

Банк: исходный Windows-OCR индекс 9 PDF / 64 страницы / 131 фрагмент, 74 поисковых.
Историческая сталь 2021 и неизвестная дата золота исключены по умолчанию. Даты/страницы,
as_of, ограничения сегмента, периоды и оговорки сохраняются. Числа OCR не прошли полную
ручную проверку; перенос наблюдения об автомобилях на спрос одежды запрещён без подтверждения.

Новости: три официальных RSS двух издателей — Банка России и Росстата. Поддерживается публичный
RSS-интерфейс; исходные HTML/XML и атрибуция сохранены в `data/news_sources/`, HTML не исполняется.
Если издатель передаёт содержательный текст в RSS, он используется с явным обозначением
`publisher_rss`: отдельная HTML-страница не считается прочитанной. Пустое описание не
превращается в статью. Полный сохранённый текст не заменяется коротким RSS при сбое сайта.
В комплекте исходные десять публикаций и ещё сорок полных статей; происхождение и хеши
RSS указаны в `data/news_current_provenance.json`. Правила доступа и транспорт описаны
в [обновлении источников](docs/DATA_UPDATES.md).

```powershell
.\.venv\Scripts\python.exe -X utf8 -m alfa_app refresh --limit 5
```

Команда обновляет runtime, без генерации. Одинаковые URL/тексты не размножаются, новая
редакция сохраняет идентичность новости. Ошибки/пустая выдача не создают вымышленных статей.
`--export-snapshot` дополнительно перезаписывает поставляемый исторический снимок: применять
только как явное обновление данных с проверкой, не для обычной демонстрации.

Банковский корпус обновляется отдельно, в новую папку, с проверкой дат, цитат и смыслового
индекса; рабочий индекс автоматически не заменяется:

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/update_bank.py --manifest data/research_manifest.json --pages data/research_pages.jsonl --output-dir var/bank/2026-10-24-review
```

Для нового корпуса сначала подготовить проверенный manifest и OCR-страницы. Если исходные
PDF доступны, добавить `--pdf-dir ПУТЬ` для сверки хешей. Активация — явно задать
`ALFA_RESEARCH_DATABASE` и перезапустить сервер. Дата неизвестна — материал не считается
текущей позицией банка. Подробности — в том же документе об обновлении источников.

## Устройство и проверки

Собственный Python-агент: выбор задачи → план → профиль/ранжирование → локальный E5 + FTS5/BM25 →
JSON draft → локальная проверка → model review → исправление/новый поиск либо остановка.
Максимум шесть фрагментов с полными страницами и два раунда по умолчанию. Частные договоры
не ищутся в макро-PDF. Профили и RSS рассчитываются без генеративных моделей.

Архитектура: [ARCHITECTURE](ARCHITECTURE.md). Контракт: [API](API.md).
Компоненты и права: [THIRD_PARTY_NOTICES](THIRD_PARTY_NOTICES.md).

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
node --test tests/test_web.mjs
.\.venv\Scripts\python.exe -X utf8 check_corpus.py
.\.venv\Scripts\python.exe -X utf8 scripts/evaluate_search.py
.\.venv\Scripts\python.exe -X utf8 scripts/evaluate_quality.py
.\.venv\Scripts\python.exe -X utf8 scripts/evaluate_acceptance.py
.\.venv\Scripts\python.exe -X utf8 scripts/evaluate_news_search.py
.\.venv\Scripts\python.exe -X utf8 scripts/verify_http.py
.\.venv\Scripts\python.exe -X utf8 -m alfa_app.llm probe
docker compose run --rm alfa-news python -X utf8 -m unittest discover -s tests -v
docker compose run --rm alfa-news python -X utf8 check_corpus.py
```

Node нужен только для UI-тестов с синтетическим DOM/HTTP. Настоящий браузер проверяется
отдельно; моки не доказывают live-генерацию. Маленькая контрольная выборка, наблюдаемые
ошибки и процесс экспертной обратной связи — [QUALITY](docs/QUALITY_2026-10-22.md).
Новый контроль: 40 полных публикаций вне исходного снимка, пять отраслей и два ракурса,
400 сочетаний ранжирования. Разметка инженерная, не независимая экспертная оценка.

Сессия/авторизация банка смоделированы выбором компании и роли. Реальная IAM-интеграция
не подключена. Ключ только backend, CSP/textContent и безопасные URL, same-origin action token,
ограниченные инструменты, журналирование. Перед промышленной эксплуатацией нужны серверная
авторизация, разграничение доступа к компаниям, TLS, эксплуатационный аудит и нагрузочные проверки.

## Поставка и ограничения

Создать ZIP без секретов, runtime, резервных копий, Git и dev-инструментов:

```powershell
python -X utf8 scripts/package_release.py --output var/releases/alfa_service_integrity_2026-10-24.zip
```

Архив текущей поставки появится в `var/releases/`.
Прежний `alfa_service_audited_2026-10-24.zip` относится к v22 и сохраняется отдельно.
`SOURCE_MANIFEST.json` фиксирует SHA-256 включённых файлов.
Перед передачей распаковать отдельно и повторить запуск/проверки. Финальная конкурсная
сдача — **один GitHub-репозиторий** с историей и commit/tag к **26.10.2026 18:00 МСК**.
Владелец команды предоставляет `alfa-hack-2026` доступ к private-репозиторию и отправляет
ссылку в кабинет. Не публиковать оригинальные закрытые CSV/PDF без установленного права.
Хостинг необязателен; презентация требуется на финале.

Веса `model.onnx` больше обычного лимита GitHub на файл: для них добавлена `.gitattributes`

## Локальный запуск и внешний доступ

По умолчанию сервер слушает `127.0.0.1`. Внешняя привязка отклоняется, пока явно
не задано `ALFA_ALLOW_REMOTE_BIND=true`. В Compose это разрешение действует внутри
контейнера; опубликованный порт остаётся на `127.0.0.1`. Для ручного docker run также
нужны явное разрешение внутренней привязки и `-p 127.0.0.1:8000:8000`.

Приложение является локальным демо без банковской аутентификации. Токен действий
из `/api/status` защищает контекст браузерного действия, но не устанавливает личность
и права пользователя. Публичное развёртывание требует настоящей аутентификации,
разграничения прав, rate limiting и пользовательских квот LLM. Один флаг привязки
не заменяет эти меры. Подробности: [границы развёртывания](LOCAL_DEPLOYMENT.md).
