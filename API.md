# JSON API

Контракт v23 от 24.10.2026. CLI по умолчанию — 127.0.0.1:8000;
рекомендованный `scripts/start.py --port 8002` использует 8002.
Пять обезличенных профилей предоставленного набора; банковская авторизация не подключена.

| Метод и маршрут | Назначение |
|---|---|
| GET /api/status | Конфигурация без ключа, число новостей, action token, статус демо |
| GET /api/health | Локальная готовность, режим/модель/индекс поиска, число профилей; без вызова LLM |
| GET /api/companies | Доступные компании |
| GET /api/companies/{id} | Прежний полный профиль |
| GET /api/news?company_id=U_1595&role=cfo | Лента с reasons, context_fingerprint, cached_run_id последнего проверенного результата, latest_run_id/latest_status последней реальной попытки анализа |
| GET /api/search?company_id=U_1595&role=cfo&as_of=2026-10-22&q=... | Поиск новостей по смыслу и словам: items, search_mode, query, as_of; q от 1 до 500 символов |
| GET /api/source?source_id=alfa_inflation&page=1 | OCR физической страницы и метаданные |
| GET /api/runs/{id} | Сохранённый результат и trace |
| GET /api/jobs/{id} | Состояние фонового задания, этап и готовый run либо отчёт обновления |
| GET /api/metrics | Агрегаты вызовов, ошибок, времени, заданий и отзывов; без ключа |
| POST /api/jobs | Постановка анализа или operation=refresh; HTTP 202 |
| POST /api/feedback | feedback_id (32 hex), run_id, rating helpful/incorrect/irrelevant, comment до 1000 символов; идемпотентное сохранение |
| POST /api/refresh | Загрузка RSS/статей и дедупликация; body: {"limit":5} |
| POST /api/insights | Поиск/агент: company_id, event_id, role, mode, question; необязательные as_of, task, parent_run_id, candidate_run_id, regenerate, request_id |

POST требует Content-Type: application/json и X-Alfa-Action из /api/status. Cross-origin действия отклоняются. Ключ не принимается от браузера и не возвращается в status.

Штатный интерфейс передаёт `async:true` в `/api/insights` и `/api/refresh`, получает HTTP 202
с `job_id`, `state` и `progress`, затем читает `/api/jobs/{id}`. Состояния задания:
queued/running/done/failed. done означает завершение обработки; содержательный статус
анализа находится в `run.status` и может быть отказом. Обычные дубликаты активного контекста
возвращают то же задание; regenerate с новым ID независим. После рестарта незавершённые задания отмечаются failed;
самопроизвольного нового платного запроса нет. Синхронный контракт сохранён для совместимости.

Оба режима `/api/refresh` используют эту же очередь и дедупликацию по `limit`.
Без `async:true` ответ остаётся готовым отчётом (HTTP 200); async возвращает задание
(HTTP 202). При переполнении — HTTP 503 с `code=queue_full`. Не более двух синхронных
ожиданий refresh/live выполняются одновременно; остальные получают тот же 503,
чтобы HTTP-потоки оставались доступны для статуса и других действий. Ошибка задания
refresh возвращает 503 без предупреждения о платной модели. Ошибки отдельных
издателей по-прежнему находятся в `report.errors` при HTTP 200; они не скрываются.
После завершения явный новый refresh создаёт новое задание и проверяет обновления.

Для `/api/source` пропущенный `page` означает 1. Явно пустое значение, дробь, строка,
ноль, отрицательное число или число за пределами положительного SQLite INTEGER
(максимум 9223372036854775807) дают HTTP 400. Отсутствующая страница также даёт 400,
как в прежнем контракте. Значение `01` остаётся допустимым номером страницы 1.

```json
{
  "company_id": "U_1595",
  "event_id": "ID_из_ленты",
  "role": "cfo",
  "mode": "sources",
  "question": "",
  "as_of": "2026-10-21"
}
```

mode=sources не вызывает API. mode=live требует серверных ключа и ALFA_ALLOW_LIVE_LLM=true. Роли: cfo/ceo. Вопрос до 500 символов. Публикации из будущего относительно as_of не анализируются.

Статусы: sources_ready — источники без генерации; low_relevance — достаточной связи нет; complete — основной инсайт прошёл локальные проверки и review; answered — ответ на уточняющий вопрос; insufficient_evidence — нехватка источников; validation_failed — неверные ссылки/цитаты/смысл после ограниченного исправления; generation_unavailable — ошибка генерации, формата, ключа, бюджета или сети; stale_result — исторический ответ, не прошедший текущую версию контекста. complete содержит insight, answered содержит answer. stale_result не возвращает прежние insight/answer как актуальные. Одобрение модели не превращает гипотезу в факт.

task принимает insight, explain, missing_data, sources. Без task агент распознаёт тип вопроса. missing_data перечисляет конкретные пробелы по профилю без LLM (answer_origin=rules); sources всегда выполняет только поиск. explain формирует короткое пояснение с проверкой источников и review, без обязательного полного набора рисков и возможностей. parent_run_id может передать актуальные источники основного вывода. candidate_run_id — сохранённый ответ на тот же вопрос для повторной проверки: компания, роль, дата, модель, профиль, новость, индекс и вопрос должны совпасть. Прежнее одобрение не используется. Ошибочный или обрезанный JSON не восстанавливается.

context_fingerprint включает компанию, полный профиль, роль, вопрос, тип задачи, дату анализа, версию новости (текст/заголовок/даты/URL), индекс банка, модель, реальные тексты промптов/формы ответа и хеш загруженной версии backend, включая retrieval. Для explain также включены ID и содержимое актуального основного ответа. Явный parent_run_id должен указывать на актуальный complete того же company/event/role/as_of; иначе HTTP 400 без генерации. Изменение/отзыв parent делает прежнее пояснение stale_result. parent не используется неявно как candidate. Перезапуск обязателен после изменения Python-кода; старый процесс сохраняет хеш реально загруженной версии. GET /api/runs сверяет актуальный контекст. cached_run_id позволяет другому браузеру открыть уже проверенный основной результат без новой генерации; клиент дополнительно сверяет fingerprint.

bank_evidence содержит evidence_id, page, дату, текст и PDF URL. trace — plan/retrieve/draft/check/model_review/replan/response_error/stop. Интерпретации, риски и возможности имеют evidence_ids, company_fields и conditional=true. Цитаты банка и новости проверяются раздельно.

По умолчанию `Settings.from_env()` выбирает `ALFA_SEARCH_MODE=hybrid`. В `bank_evidence`
добавлены `retrieval_method`, `semantic_score`, `semantic_rank`, `lexical_rank`, `hybrid_score`.
В результатах поиска новостей `search_match` содержит метод, cosine и `exact_match`.
Эти поля показывают близость при поиске, а не достоверность вывода. Прежние reasons и
business_score сохраняют персонализацию по компании/роли; дата отсекает будущие публикации.
Смена режима, политики, модели или векторного индекса меняет fingerprint ответа.

В hybrid кандидаты объединяются из плотного канала и сильных текстовых совпадений.
Порог cosine 0.82 применяется к плотному каналу; точная фраза или все значимые термы
могут сохранить текстовый результат ниже этого порога. Одно частичное OR-совпадение
такого права не даёт. У текстового кандидата semantic_rank может быть null,
semantic_score остаётся фактическим, а lexical_rank/hybrid_score объясняют ранжирование.
Для новостей проверяется весь текст, включая часть за пределами окна embeddings.
Режим semantic сохраняет прежний строгий порог. Версия объединения возвращается как
search.ranking_policy_version; индекс векторов и его кодирование не менялись.

Смысловой поиск: локальный multilingual-e5-small (ONNX int8), 384 измерения; ни тексты,
ни вопросы не отправляются в службу embeddings. При недоступной модели/индексе — HTTP 503,
без скрытого перехода к поиску по словам. Явный `ALFA_SEARCH_MODE=lexical` доступен для сравнения.

Синхронный live-запрос использует сохранённое задание, ожидает его и
возвращает прежнюю форму run. Повтор того же ID возвращает прежний результат; failed
даёт HTTP 409 с code=previous_attempt_failed, для новой попытки нужен новый ID.
Старый синхронный контракт без ID сохранён: активные одинаковые запросы объединяются,
но гарантии идемпотентности повторной доставки после завершения без ID нет. Штатный асинхронный
маршрут возвращает то же обычное активное задание (HTTP 202). После сохранения результат восстанавливается
из runtime. Явный `candidate_run_id` также может указать полный JSON черновика из прежнего
`validation_failed`/`generation_unavailable`: только если он сохранён целиком в кеше, подходит
контексту, заново проходит все текущие локальные проверки и новый review. Усечённый JSON не
восстанавливается. В review передаются полные страницы всех цитируемых банковских источников;
неиспользованные страницы туда не добавляются.

Для проверки смысла в модель передаётся полная страница каждого выбранного источника, без дублирования одинаковой страницы; общий контекст ограничен размером. Период наблюдений отделён от даты публикации, факт — от прогноза и сценария. scope_note и краткий вывод обязаны показывать границы переноса между сегментами. Точные даты, обозначения отчётов и подписанный ОКВЭД проверяются как метаданные, а не финансовые показатели; произвольные числа остаются запрещены. Кредитный маркер не устанавливает действующий долг.

При ошибке формата error.diagnostics и response_error в trace содержат безопасные метаданные: reason, finish_reason, requested_max_tokens, число символов content/reasoning_content и usage, если шлюз его вернул. Сам текст ошибочного ответа и рассуждений не публикуется. llm_request_attempted отмечает попытку вызова даже при ошибке разбора. Форматный сбой останавливает запуск; он не запускает повторный поиск. Семантическая нехватка доказательств по-прежнему может вести к replan.

/api/status также возвращает draft_max_tokens, review_max_tokens и timeout_seconds. Лимиты черновика/review независимы: 8192/6144 по умолчанию. Диагностика содержит stage, call_id, attempt, request_bytes, elapsed_ms и usage.completion_tokens_details.reasoning_tokens, если шлюз их вернул. cached=true обозначает повторное использование ранее полученного ответа без нового запроса; usage в таком шаге относится к исходному вызову и не должен повторно суммироваться как расход.

В replan доступны конкретные замечания и unavailable_queries: индивидуальные данные клиента, которых нет в корпусе банка. В модель передаются prior_review_issues. Опорные источники сохраняются при дополнительном поиске. invalid_draft_schema/invalid_review_schema обозначают ошибку структуры, а не подтверждённый недостаток источников.

revise означает исправление по уже найденным полным страницам; replan — обоснованный новый поиск. next_round_will_run=false показывает, что предложенный следующий раунд не выполнялся. candidate_recheck явно отмечает непроверенный прежний черновик. При открытии готовой карточки интерфейс добавляет restore_result; сохранённые диагностические поля исходных вызовов остаются историей, а не новым расходом.

## Шлюзы и бюджет · аудит 22.10.2026

Backend допускает только https://changellenge.up.railway.app/v1 и
https://api.alfahack-gateway26.ru/v1 (допустим один завершающий slash). HTTP, другие хосты,
порты, userinfo, query/fragment и лишние пути отклоняются. Авторизованные HTTP-редиректы
не выполняются. /key/info использует только документированный основной адрес
https://changellenge.up.railway.app/key/info, даже если генерация настроена на альтернативный.

Локальный счётчик и блокировка budget_exceeded общие по ключу: смена модели/адреса не
создаёт новый cap. Каждая фактическая попытка резервируется в своём периоде.
Транспортные повторы отключены: тайм-аут, HTTP 408/429/5xx и сетевой обрыв могут
следовать за обработкой запроса. Ошибка request_outcome_unknown содержит предупреждение
о возможном повторном расходе при ручной перегенерации. 401/403 и budget_exceeded
также не повторяются; блокировка бюджета действует до сброса. Кеш не создаёт calls.
Цены и единицы balance неизвестны, произвольный ответ шлюза наружу не передаётся.

`ALFA_LLM_MODEL` задаёт модель черновика, `ALFA_LLM_REVIEW_MODEL` — отдельной проверки.
По умолчанию это `deepseek/deepseek-v4.1-flash` и `google/gemma-4-26b-a4b-it`.
Обе настройки проверяются по тому же списку шести моделей. `/api/status`, trace и
диагностика вызова содержат фактически выбранную модель этапа, без ключа.
Fingerprint результата включает обе модели; смена review-модели требует нового review.
Локальные проверки источников обязательны при любом выборе моделей.

`ALFA_LLM_RECOVERY_MODEL` выбирает разрешённую резервную модель черновика. Только
`output_truncated` и `reasoning_without_answer` запускают один `draft_recovery` за анализ.
Он использует тот же ключ, шлюз, локальный cap и денежный бюджет. Trace содержит
`generation_recovery` с исходной безопасной диагностикой; фактическая модель черновика
записана в `draft_result.model` и `run.model`, запрошенные модели — в provenance.
`generation_recovered=true` означает, что после обрыва получен новый полный JSON;
готовность всё равно определяется status и результатами локальной проверки/review.

Полный путь известного признака может быть однозначно дополнен префиксом `company.` (например, `products.credit` → `company.products.credit`). Это отражается в trace; цитаты, утверждения, отсутствующие поля и неполный JSON не исправляются. Все локальные проверки и новый review обязательны.


## Независимые анализы и ручная перегенерация · v22

В `/api/insights` и `/api/jobs` `regenerate:true` допускается только с `mode:"live"`
и `request_id` из 32 строчных hex-символов. Неверные значения возвращают HTTP 400.
Этот режим пропускает готовый результат, candidate_run_id и кеш прежнего черновика;
новая генерация и новый review сохраняют обычные проверки. Trace содержит regenerate.
Повтор того же request_id для того же контекста возвращает то же задание, даже после
завершения или failed. Новый идентификатор с regenerate=true создаёт независимое
задание даже при активном анализе. Обычные дубли объединяются; все присоединившиеся ID
сохраняются в job_requests одной транзакцией. Повтор их доставки после завершения
также не запускает новый платный вызов.

У разных вопросов и статей независимые задания; одновременно работают два worker.
ALFA_MAX_ACTIVE_JOBS задаёт положительный предел queued + running (по умолчанию 16).
Одинаковое активное задание объединяется до проверки ёмкости. При заполнении оба
HTTP-сервера возвращают 503 с code=queue_full; новые задания не создаются. GET news/search возвращает
latest_run_id и latest_status последней реальной попытки, включая validation_failed и
generation_unavailable. cached_run_id по-прежнему указывает на проверенный complete.
Неуспешный анализ не подменяет проверенное основание для уточнения.

`ALFA_MAX_CALLS_PER_PERIOD=0` (по умолчанию) отключает внутренний предел числа попыток.
Положительное значение задаёт необязательный предел. При отключённом пределе metrics
возвращает `local_call_cap:null` и `calls_remaining:null`; фактические попытки учитываются.
Официальные budget_exceeded/500 ₽ и период ключа действуют независимо от этой настройки.


`job.context` содержит company_id, role, event_id, as_of, mode, нормализованный task,
полный question и parent_run_id (для explain; в остальных задачах null). Браузерный
ключ pending.v2 включает все эти поля, а для regenerate ещё regenerate и request_id.
Намерение запроса с ID сохраняется до POST отдельно: потеря ответа до получения job_id
не меняет ID при ручном повторе после reload. Восстанавливается только полное совпадение,
а удаление указателя требует совпадения job_id. Старые неполные ключи pending.v1
не используются для автоматического восстановления. Сама история заданий сохраняется.

`request_id` обеспечивает дедупликацию в локальной очереди, но не является
идемпотентностью внешнего шлюза. Вызов LLMClient.generate выполняет не более одного
POST. diagnostics.transport_retry_performed=false; при неоднозначном исходе
diagnostics.request_outcome_unknown=true. Новый draft_recovery после полученного
обрыва length остаётся отдельной ограниченной генерацией с новым учётом и trace.
Проверка цитат и отдельный review сохраняются.

Длинная новость передаётся как выборка дословных фрагментов из всего текста, до
3500 символов вместе с разделителями. В news_context результата записаны original_chars,
selected_chars, context_incomplete, omitted_important_fragments и context_warning.
В модели также есть selected_spans с точными позициями. Проверка цитат использует
полный оригинал, а не склеенную выборку. Предупреждение о неполноте видно пользователю.

HEAD статических ресурсов и читающих API возвращает заголовки GET без тела ответа.
Внешняя привязка запрещена по умолчанию; токен действий не является авторизацией.

При обновлении новости прежний хеш текста не блокирует исправление заголовка, даты
и других метаданных. ID, история и кеш сохраняются. retrieved_at/raw/RSS-хеши сами по
себе не меняют fingerprint и не вызывают модель. Исправление заголовка/даты меняет
содержательный контекст и отзывает прежнее одобрение; новая генерация требует действия.

SIGTERM/SIGINT запрещают новые этапы до ожидания HTTP-потоков. Docker grace — 210s:
один текущий timeout до 180s и завершение. При аварийном убийстве reserved-вызов после
restart получает interrupted_outcome_unknown; резерв расходов не возвращается,
платная работа не повторяется автоматически. Пользователь видит предупреждение.
