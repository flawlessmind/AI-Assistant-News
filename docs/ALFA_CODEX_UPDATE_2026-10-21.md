# Обновление для Codex: Альфа-Будущее 2026, кейс №3

Продолжай существующий проект «Новостная аналитика для принятия бизнес-решений». Не начинай заново EDA, профайлер или OCR. Рабочая основа этого обновления — приложенный пользователем `alfa_step2.zip`, а не другие одноимённые или более ранние пакеты.

Дедлайн по подтверждённому сообщению организаторов: **26 октября 2026, 18:00 МСК** — [сообщение 5080](https://t.me/alfafuture_hack/5080).

## Самое важное из новых разъяснений

1. **Base URL теперь известен:** `https://changellenge.up.railway.app/v1`.
2. **Бюджет обновляется в 03:00 МСК.** В старом handoff было 00:00; это нужно заменить по новой официальной инструкции.
3. **Для проверки эксперты используют собственные ключи.** Ключ команды не передаётся в коде; нужна конфигурация через окружение.
4. Python/Node.js-библиотека `openai` разрешена как клиент официального API для разрешённых моделей. Агентную логику всё равно пишем сами.
5. Отдельная регистрация и реальная тестовая интеграция с Альфа-Бизнесом не требуются. Нужны рабочий веб-сценарий, стилистика и точка входа из интернет-банка.
6. На отборочном этапе презентация не требуется: сдаём код и предусмотренные ТЗ материалы для запуска. Презентация нужна на финале.
7. Приложенный проект реально проходит **9 unit-тестов и 12 проверок корпуса**. Полного приложения, LLM-клиента и адаптивного агента пока нет.

`/key/info` находится **вне `/v1`**. В OpenAI SDK передаём именно base URL с `/v1`, а не полный адрес chat-запроса. Обычный HTTP-маршрут Chat Completions при такой совместимости — `/v1/chat/completions`; это следует из примера SDK, отдельно запрос с ключом здесь не выполнялся.

Точные разрешённые `model` ID — копировать без сокращений:

```text

z-ai/glm-5.3-flash
qwen/qwen3.6-35b-a3b

moonshotai/kimi-k2.6
```

Названия подтверждены PDF и [7538](https://t.me/alfafuture_hack/7538). Использование библиотеки `openai` как HTTP-клиента для этого шлюза прямо разрешено в [6620](https://t.me/alfafuture_hack/6620); это не разрешение вызывать GPT или иные модели вне списка.

Предлагаемая конфигурация будущего клиента — этих переменных в текущем приложенном коде ещё нет:

```dotenv
ALFA_LLM_BASE_URL=https://changellenge.up.railway.app/v1
ALFA_LLM_API_KEY=
ALFA_LLM_MODEL=deepseek/deepseek-v4.1-flash
```

DeepSeek здесь выбран только потому, что используется в официальном примере; это не результат сравнения цен или качества. Реальный ключ хранится локально/в окружении сервера. Не включать его в репозиторий, клиентский JavaScript, тестовые фикстуры или журналы. При диагностике организаторам передают название ключа и текст ошибки, а не секрет — PDF.

### Что ещё не известно об API

Инструкция не сообщает цены по моделям, RPM/TPM, concurrency, размеры контекста, максимальный ответ, поддержку strict JSON/schema/function calling и точную схему ответа `/key/info`. Не выдумывать эти параметры или стоимость токена. При чтении баланса проверить единицы: нельзя автоматически трактовать любое число ответа как рубли.

Получение и работоспособность ключа **конкретно нашей команды не подтверждены**. Объявление о рассылке всем капитанам — отдельный факт, не проверка нашего ключа. В этом разборе платных запросов не было.

В бюджете учитывать границу суток в 03:00 `Europe/Moscow`; для локального идентификатора периода подходит дата от московского времени минус 3 часа. При `Budget has been exceeded` остановить генерацию до следующего сброса, не запускать бесконечные повторы. OCR и поиск остаются локальными.

## 6. Следующая конкретная задача Codex

Пользователь ожидает работающий сервис, а не новое общее планирование. Сохрани готовые функции и форматы, добавляй недостающие компоненты небольшими проверяемыми шагами.

1. **Конфигурация и LLM-клиент.** Добавь официальный base URL и allowlist ровно шести model ID, ключ из окружения, `.env.example`, timeout, ограниченный ответ, обработку ошибки бюджета, локальный кеш. Сделай отдельную небольшую проверку соединения; выполнять реальный запрос только если ключ доступен локально и явно выбран такой режим. Не выводить ключ в ответ пользователю. Не объявлять live-интеграцию проверенной без успешного запроса.
2. **Реальные новости.** Реализуй воспроизводимый загрузчик из выбранных открытых первичных источников: дата события и публикации, URL, сохранённый исходный текст, хеш, устранение дублей. Добавь возможность проверить ранее не использованную новость. Конкретные RSS-адреса нужно проверить, а не выдумать. Исторический JSON от 11 сентября оставить тестовым примером.
3. **Персонализация до генерации.** Объяснимо ранжируй события по подтверждённым признакам компании; отдельно храни использованные поля и причины. Не подменять этот этап поиском PDF. Проверять как минимум U_1595 и U_83932.
4. **Собственный адаптивный цикл.** Реализуй plan → tools/retrieve → draft → check → retry/stop, общий контекст и trace. При недостаточном доказательстве меняй поиск либо возвращай «недостаточно данных». Последовательность фиксированных поисковых вызовов из `prepare_evidence` сама по себе не закрывает агентность. Наличие SDK `openai` не реализует оркестрацию.
5. **Первый рабочий экран.** Выбор компании → события/лента → карточка с фактом, позицией банка, условной интерпретацией, рисками/возможностями, действиями и источниками. Предусмотри точку входа из макета Альфа-Бизнеса и переход к странице PDF. Ключ только на backend. FastAPI/React были предложением, не готовыми компонентами; выбирать реализацию с учётом срока.
6. **Воспроизводимость и сдача.** Docker, фиксированные зависимости, README с конфигурацией чужого ключа, THIRD_PARTY_NOTICES, проверка чистого запуска и неизвестной новости. GitHub с историей и финальным commit/tag до дедлайна; для private-репозитория доступ `alfa-hack-2026` по ТЗ. Наличие презентации не должно задерживать онлайн-сдачу.

Для снижения расхода API: не отправлять весь PDF-корпус и весь CSV в LLM; готовые профили и поиск работают локально, в модель передавать небольшой evidence pack. Не предполагать заранее поддержку streaming, tool calls или строгой JSON schema всеми шестью моделями.

**Критерий ближайшего результата:** одна новая реальная новость проходит загрузку и дедупликацию, для двух компаний даёт разные обоснованные причины релевантности, получает банковские доказательства и вывод через разрешённую LLM; видны источники, неопределённость и trace. Нехватка доказательств/ошибка API показывается честно. До появления ключа можно реализовать и проверить остальные компоненты, но не выдавать их за испытанную LLM-генерацию.
