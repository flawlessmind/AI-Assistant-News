# Альфа Хакатон, кейс 3: продолжение с этапа 2

Состояние на 20 октября 2026 года. Это рабочий модуль данных и поиска с проверяемым примером инсайта. Полное конкурсное приложение ещё не собрано.

## Что мы делаем простыми словами

Руководитель выбирает свою компанию. Сервис находит важные для неё новости, объясняет возможные последствия, привлекает аналитику Альфа-Банка и показывает доказательства. Одна и та же новость должна давать разные объяснения для разных компаний.

Пример: у торговой компании отмечен кредитный продукт. Новость о ставке нужно связать с условиями финансирования и особенностями розничного бизнеса. Размер долга, рост расходов и падение продаж из одного признака кредита вывести нельзя.

## Что пока не реализовано

- Автоматическое обновление новостей, RSS-парсер и удаление дублей. Новость Банка России от 11.09.2026 сверена вручную с первоисточником и явно помечена историческим примером.
- Ранжирование целой новостной ленты для разных клиентов. Подбор банковского контекста в prepare_evidence.py не заменяет этот компонент.
- Разрешённая генеративная LLM и собственный адаптивный агент: планирование, вызовы инструментов, смысловая самопроверка, повторный поиск при недостатке данных. Текущий trace относится к детерминированному поиску.
- Сервер API, пользовательский интерфейс, уточняющий диалог, разграничение доступа.
- Docker для всего приложения, окончательная фиксация зависимостей всех компонентов, GitHub-сдача и проверка чистого запуска.

Python и SQLite уже используются. FastAPI, React и Docker Compose остаются предложением для следующей интеграции; считать их реализованными нельзя.

## Что можно запустить прямо сейчас

Для поиска по готовому индексу достаточно Python со стандартными модулями sqlite3 и FTS5. Проверено на Python 3.12.14. Команды выполняются из этой папки:

```powershell
python -X utf8 alfa_research.py search "ключевая ставка пауза кредиты" --as-of 2026-10-20 --limit 3
python -X utf8 alfa_research.py search "розничная торговля потребление спрос" --as-of 2026-10-20
python -X utf8 alfa_research.py search "золото ФРС" --as-of 2026-10-20 --include-undated
```

Собрать индекс заново из уже распознанных страниц, без OCR и без сети:

```powershell
python -X utf8 alfa_research.py build
```

Подготовить доказательства для конкретного профиля и датированного события:

```powershell
python -X utf8 prepare_evidence.py --profile data/company_U_1595.json --event data/news_event_cbr_2026_09_11.json --as-of 2026-10-20 --output data/evidence_pack_U_1595.json
python -X utf8 prepare_evidence.py --profile data/company_U_83932.json --event data/news_event_cbr_2026_09_11.json --as-of 2026-10-20 --output data/evidence_pack_U_83932.json
python -X utf8 check_corpus.py
python -X utf8 -m unittest discover -s tests -v
```

Каждый результат содержит evidence_id, source_id, page, publication_date, source_url, pdf_sha256 и исходный OCR-текст. page — физический номер страницы PDF с 1; печатный номер на листе иногда отличается. Google Drive может проигнорировать #page= в ссылке, поэтому номер страницы передаётся отдельно.

Проверка точного совпадения цитаты:

```powershell
python -X utf8 alfa_research.py verify-quote --source-id alfa_policy_rate --page 1 --quote "Мы ожидаем сохранения паузы на заседании 23 октября"
```

Она проверяет присутствие текста, а не истинность вывода и не качество распознанного числа.

## Повторить распознавание исходных PDF

Скачать 9 PDF из [папки организаторов](https://drive.google.com/drive/folders/15xZTLF1lZ65p6o5xpNA_fRbxjoV-UlG1) в data/raw с исходными именами. Список файлов, ожидаемые размеры и SHA-256 находятся в data/research_manifest.json. Сырые PDF в этот небольшой комплект не вложены.

```powershell
python -m pip install -r requirements.txt
python -X utf8 alfa_research.py extract --pdf-dir data/raw --ocr-engine windows
python -X utf8 alfa_research.py build
```

Для OCR нужны Poppler/pdftoppm в PATH и русский распознаватель Windows.Media.Ocr. Этот путь реально выполнен на текущем Windows-компьютере. Распознавание не использует генеративную LLM. [Документация Windows OCR](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr.ocrengine).

В коде есть альтернативная ветка --ocr-engine tesseract для среды с Poppler и Tesseract rus+eng; здесь она не проверялась. Готовые research_pages.jsonl и research.sqlite можно использовать без Windows OCR. Перенос всего сервиса в проверенный Docker — отдельная следующая задача.

Исходный профиль по CSV воспроизводится прежней командой; CSV доступны в [папке компаний](https://drive.google.com/drive/folders/1Ep8wWoEHTg5Q8kwrLx2j_xFyxGUEVxFq):

```powershell
python -X utf8 alfa_profiles.py --data-dir data/companies --company-id U_1595 --output data/company_U_1595.json
```

## Ограничения поиска

Поиск лексический: явные префиксы русских терминов, покрытие запроса и BM25. Это первый retrieval-компонент для будущего RAG, без эмбеддингов и генерации. Он может пропустить синонимы и вернуть слабосвязанный фрагмент; поиск ещё не оценивает смысловую достаточность.

По умолчанию исключаются документы из будущего относительно --as-of, документы старше 365 дней и документы без подтверждённой даты публикации. --include-historical возвращает старый обзор с соответствующей меткой. --include-undated включает источники с неизвестной датой и предупреждением; использовать их для исторического вывода без дополнительной проверки нельзя.

В индексе сохранены все страницы, включая таблицы и дисклеймеры. Поиск ограничен содержательными фрагментами; служебные страницы и ряд страниц только с таблицами/графиками исключены, также применяется простой фильтр количества слов. Он не гарантирует полного удаления графического шума. Табличные числа автоматически достоверными не считаются.

OCR ошибается в процентах, десятичных знаках и названиях; например, 14,0% может превратиться в 14,00/0. Для первого инсайта нужные утверждения сверены с изображениями оригинальных страниц. Все числа всего корпуса вручную не проверены. Датированные прогнозы банка не превращаются в факты; автоматическое разрешение противоречий ещё предстоит реализовать.

## Следующий конкретный шаг

Написать настоящий загрузчик новостей из двух согласованных первичных источников, сохранять дату/URL/текст, удалять дубли и пропускать через текущий поиск. Проверка результата: добавить ранее не использованную новость, сменить компанию и получить другой обоснованный набор причин релевантности. Затем подключить выданный API, реализовать собственный агентный цикл и вывести карточку в интерфейс.

Для продолжения кода ключ пока не нужен. Для проверки генерации потребуются ключ организаторов, endpoint, точные идентификаторы моделей, цены и rate limits. Ключ хранится локально в переменных окружения; в репозиторий и открытые сообщения его не помещают.

Сверять обязательные требования нужно с официальным ТЗ в docs/case_spec.pdf и разъяснениями организаторов. Handoff служит историей состояния и предложений. По сообщению организаторов и предоставленному контексту сдача — 26 октября 2026 года, 18:00 МСК.
