# Альфа-Будущее Хакатон — кейс 3. Анализ исходных данных

Дата анализа: 20 октября 2026. Источник: предоставленные организаторами CSV из [Google Drive](https://drive.google.com/drive/folders/1Ep8wWoEHTg5Q8kwrLx2j_xFyxGUEVxFq).

## Структура

| Таблица | Число записей | Что содержит |
|---|---:|---|
| `df_Uid_data_hack.csv` | 85 525 | 24 признака компаний: отрасль, регион, выручка, признаки банковских продуктов, группа компаний |
| `df_Fid_Uid_link_hack.csv` | 12 514 | Связи обезличенных физических и юридических лиц |
| `df_Uid_payment_hack.csv` | 1 380 585 | Плательщик, получатель, сумма и число платежей |

Основная таблица имеет **85 514 различных идентификаторов**. ID `U_428697` встречается 12 раз с **разными** отраслевыми и региональными признаками — нельзя автоматически считать эти строки одной компанией; до прояснения рекомендуется исключить этот ID из соединений.

## Релевантность для крупного бизнеса

По критерию выручки от 15 млрд (единицы выручки нужно подтвердить у организаторов) подходят **115 компаний**, причём 102 из них имеют метку `CLIENT`, 6 — `CLOSE_CLIENT`, 7 — `PROSPECT`. У 49 крупных компаний есть маркер кредитного продукта, у 113 — записи о платежах.

Среди этих 115 компаний 62 имеют основной ОКВЭД, начинающийся с 46 (оптовая торговля), 13 — с 41 (строительство зданий). 79 компаний зарегистрированы в Москве. Для демонстрации лучше выбрать несколько разных отраслей и сценариев, а не только наиболее частую категорию.

## Качество данных и риск неверных выводов

- `AMOUNT_WORKERS_SPARK_GRADATION` пустое в 99,80% записей — нельзя опираться на него как на основной показатель масштаба.
- `FTS_COUNTRY_NAME` пустое в 90,24%; `ECO_MARK_LABEL` — в 4,86%.
- В платежах **178 159 различных участников**, из которых только **63 607** встречаются в основном справочнике компаний. Отсутствие профиля у контрагента не означает отсутствия контрагента.
- В связях физических лиц присутствуют **12 307 различных компаний**, из которых **4 519** есть в основном справочнике.
- В датасетах нет понятного по CSV периода платежей и отдельного поля валюты/единицы суммы; эти значения нельзя интерпретировать как текущие финансовые показатели без уточнения.
- Доля рынка не дана в таблицах; нужно отдельно описывать методику оценивания либо явно показывать «нет данных».

## Решение для MVP

1. Построить воспроизводимый профиль выбранной компании, с полями `industry`, `region`, `revenue`, `bank_products`, `group`, `payment_graph`, `data_quality_notes`.
2. Для новостей создать отдельную сущность `news_event` с источником, датой, сущностями, темами и подтвержденными фактами.
3. Ранжировать события для профиля на основе отрасли, региона, характера финансирования и существующих бизнес-связей, сохраняя *причины ранжирования*.
4. Агент должен по найденной новости искать релевантную аналитику банка и формировать результат по схеме «факт / позиция банка / вывод модели / неопределённость / риск / возможность / действие / источник».
5. Проверять результат на нескольких разных компаниях, новых новостях и противоречивых источниках.

### Проверенный минимальный модуль

`alfa_profiles.py` принимает ID компании и три исходных CSV, выдает JSON с обоснованным бизнес-контекстом и ограничениями данных. Пример: `alfa_example_company_profile.json` для синтетической компании `U_1595`.

```bash
python alfa_profiles.py --data-dir ./data --company-id U_1595 --output company_profile.json
```
