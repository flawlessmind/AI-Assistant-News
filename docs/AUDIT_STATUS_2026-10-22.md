- `agent.py` содержал в общих промптах обязательный пример одежды/автомобилей/июля.
  Промпты обобщены, контекст сегмента/периода передаётся источниками; прежние смысловые
  регрессии сохранены. `tasks.py` различает одежду, другую розницу, строительство и
  общий fallback. Чужая отрасль не навязывается неизвестному профилю.

- `web/app.js`: устранены две одинаковые offline-кнопки с разными задачами, пример

## Дополнение: конфликт локального порта Windows

По пользовательскому ERR_CONNECTION_TIMED_OUT воспроизведён тайм-аут 127.0.0.1:8000
при прямом запросе без прокси. Windows netstat показал два Python-listener на этом
адресе; сервер 8012 отвечал HTTP 200. Запущен и проверен браузером **8002**: HTTP 200,
загружены интерфейс, две компании и десять новостей. Новых генеративных запросов нет.
Пользовательские процессы, `.env`, VPN/proxy/firewall не изменялись.

`server.py` теперь использует SO_EXCLUSIVEADDRUSE на Windows вместо допуска второго
SO_REUSEADDR listener; остальные платформы сохраняют прежний bind. `__main__.py`
показывает понятную ошибку занятого/недоступного адреса до успешного startup-баннера.
Повторный запуск на реально занятом 8000 теперь заканчивается этой ошибкой. Проверен
и перезапуск своего сервера 8002 после Ctrl+C. Новый tests/test_server_ports.py: второй
bind отклоняется, первый сервер остаётся доступным; CLI даёт корректный другой порт.
После исправления полный набор на Python 3.12.14 — **108/108**; новые регрессии **2/2**.
В новой чистой копии ZIP повторно прошли 108 Python, 26 Node, 12 corpus, 13 quality,
offline probe и настоящий HTTP без ключа. Архив для команды обновлён.
Резервная копия до этого исправления — `var/audit_2026-10-22/port_fix_before/`.
Текущий проверенный Python-сервер с пользовательской конфигурацией —
http://127.0.0.1:8002/; прежний source-only 8012 относится к основной итерации аудита.
