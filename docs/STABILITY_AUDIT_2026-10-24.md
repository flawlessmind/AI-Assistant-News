# Проверка стабильности Alfa Service · 24 октября 2026

Версия `2026-10-24-v21-stable-attempts`. Проверены и исправлены текущие исходники после
v20. Архитектура, дизайн, модели, разрешённые шлюзы и закреплённые зависимости сохранены.
Реальная `.env` не менялась. Новых платных LLM-запросов — **0**.

## Исправленные ошибки

|---|---|---|

Контекст вопроса и родительский анализ сохранены | JS: явный повтор failed создаёт новый ID; сетевой повтор сохраняет ID. Настоящий браузер: failed → кнопка повтора → done, разные ID |
| BUG-02: regenerate присоединялся к активному анализу в браузере, очереди и внутренней блокировке | `web/app.js`, `alfa_app/jobs.py`, `alfa_app/server.py`: regenerate + request_id входят в ключ попытки. Новый nonce — отдельная генерация; тот же nonce — то же задание | Две одновременно выполняющиеся генерации; 10 конкурентных отправок двух nonce дают ровно 2 задания; повтор одного nonce не создаёт платных дублей. Старый сервер проверяет Host, Origin и неоднозначное framing, имеет timeout чтения | Оба сервера: GET/POST RuntimeError → JSON 500, следующий запрос работает; SQLite/статика → 503. В логах тип и места кода, без текста исключения, query или секретов. Матрица malformed JSON, неверный Host/Origin, пустое тело, отсутствие action token, PUT |
| Отказ executor оставлял queued без исполнителя, ошибка SQLite до try выходила из worker | `alfa_app/jobs.py`: отказ запуска записывается failed; весь worker под защитой; ошибка сохранения статуса журналируется, платная работа не перезапускается | Отказ executor не оставляет queued; одноразовая ошибка чтения SQLite до начала работы даёт failed и 0 генераций. ## Данные, безопасность и совместимость

До изменений создана согласованная SQLite backup-копия в приватной `var`. Все существовавшие
новости, jobs, runs, calls, usage, llm_cache и feedback сравнены с ней: старые строки
сохранены. Рабочие 176 записей физических вызовов и 165 строк кеша не менялись; новых
реальных LLM-вызовов нет. `PRAGMA quick_check` — ok. `.env`, исследовательская SQLite,
страницы и исходный снимок новостей сохранили контрольные суммы. Полный протокол —
`data/stability_integrity_2026-10-24.json`. Добавлена только таблица job_requests;
история и расходы не сбрасываются. CSS и HTML интерфейса не менялись.

Проверены параметризованные SQL и транзакции, textContent/CSP и безопасные URL,
CSRF/action token, отсутствие CORS-разрешения чужим origin, серверное хранение ключа,
allowlist внешних HTTPS-адресов и запрет авторизованных редиректов, границы HTTP,
дедупликация, ограниченная очередь, журнал физических LLM-попыток и общий бюджет.
В JSON ошибок нет traceback/текста внутренних исключений; серверный журнал содержит
место ошибки без запроса и секретов. Зависимости, модели и разрешённые шлюзы не менялись.
Это аудит кода и регрессионная приёмка, а не независимый пентест или сертификация.

## Оставшиеся ограничения и вердикт

| Приоритет | Состояние |
|---|---|
| P0 | Подтверждённых незакрытых блокирующих ошибок в проверенном локальном контуре нет |
| P1 | Подтверждённые ошибки повторов, расходов и HTTP исправлены. Для публичного режима блокируют отсутствие настоящей аутентификации, прав доступа к компаниям/истории/jobs, rate limiting и пользовательских LLM-квот; этот режим не объявлен готовым |
| P2 | Нужны эксплуатационные backup/restore и мониторинг диска/шлюза для длительной работы; отказ диска может помешать сохранению статуса до restart. Живой шлюз намеренно не вызывался. Числа OCR и неизвестные бизнес-параметры требуют проверки владельцем данных |
| P3 | Возможны дальнейшие нагрузочные измерения и более широкая независимая оценка качества смыслового поиска/модельных выводов |

**Локальная эксплуатация:** готова в проверенных сценариях, сервер слушает 127.0.0.1.
**Публичное развёртывание:** не готово; обязательны перечисленные IAM, права, rate limiting,
квоты, TLS и управление секретами. Action token из /api/status не является авторизацией.

**Потеря данных:** удаления/перезаписи истории при этой доработке не обнаружены, backup
создан; аппаратные отказы, удаление runtime пользователем и отсутствие регулярных копий
остаются эксплуатационным риском. Публичный архив не содержит личную runtime-БД и ключ.

**Платные вызовы:** скрытые транспортные повторы отсутствуют; один request_id не создаёт
новую платную попытку при повторной доставке в jobs/API с ID. Явная перегенерация с новым
ID — новое оплачиваемое действие, проверка и review сохранены. Локальный cap по числу
вызовов остаётся настроенным владельцем (в рабочей установке 0, то есть отключён);
официальный общий бюджет шлюза 500 ₽ и локальная блокировка после его ошибки сохраняются.
Очередь и число этапов каждого задания ограничены. Это не заменяет пользовательские
квоты для публичного сервиса. Синхронный legacy-клиент без request_id не имеет гарантии
идемпотентности: передавать стабильный ID, как встроенный браузер.
