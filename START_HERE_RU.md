# Начать здесь · 24 октября 2026

Приложение новостной аналитики для кейса №3. Интерфейс сохранён; поиск новостей и
банковских документов работает по смыслу и словам локально.
Текущий статус и границы проверок: [статус поставки](docs/RELEASE_STATUS.md).
Полная инструкция: [README](README.md).

Из корня распакованного проекта, Python 3.12 с SQLite FTS5 (закреплена версия 3.12.14):

```powershell
python -X utf8 scripts/start.py --port 8002
```

На Windows можно открыть `START_WINDOWS.cmd`. Первый запуск создаёт `.venv` и устанавливает
закреплённые зависимости; для этого нужен интернет. Модель уже включена в ZIP.
Открыть [http://127.0.0.1:8002](http://127.0.0.1:8002). Если порт занят, использовать
`--port 8003` и открыть адрес с 8003. Терминал оставлять открытым; остановка — Ctrl+C.
После изменения Python-кода перезапустить сервер; обновления вкладки недостаточно.
Существующие `.env` и `var` сохранять. Проверка без генерации: `python -X utf8 scripts/start.py --check`.

1. Выбрать U_1595 и финансового директора, открыть «Обзор бизнеса», затем аналитику.
2. Открыть релевантную новость, посмотреть причины отбора и дату анализа.
   В строке поиска написать «В магазинах изменились ценники на повседневные покупки»:
   совпадения всей фразы в заголовке не требуется.
3. Раскрыть банковские источники, страницу OCR и ссылку на PDF.
4. Задать «Каких данных не хватает для полного вывода?» — ответ правил без LLM.
5. Выбрать поиск источников и свой вопрос, раскрыть шаги проверки.
6. Переключить U_83932 и роль руководителя: старый ответ сбрасывается, приоритеты меняются.
   Дополнительно доступны производство U_87, грузовые перевозки U_768 и оптовая торговля U_84.
7. Нажать «Подготовить анализ», перейти к другой статье и запустить её анализ. Оба
   задания продолжаются в фоне. Вопросы одной статьи отображаются отдельно, с текстом
   вопроса; после перезагрузки открыть нужную кнопку в «Фоновых заданиях этой статьи».
   Возвращение к статье показывает основной результат или ошибку;
   «Перегенерировать» создаёт отдельную попытку, даже если предыдущая ещё выполняется.
   После failed кнопка «Повторить запрос» создаёт новый ID; после потери HTTP-ответа
   повтор сохраняет прежний ID. Перезагрузка сама не запускает генерацию.
8. Генерация доступна только с локальным ключом и разрешением live. Исторический ответ
   с иной датой/профилем/логикой не считается актуальным.

В чистой поставке `.env`, ключ и `var` отсутствуют. Без них доступны 50 реальных новостей из
снимка, профили, поиск и пробелы после установки зависимостей; готовый инсайт не имитируется. Эксперты используют свой
ключ по README. Не отправлять ключ в чат или frontend.

```powershell
docker compose up --build
```

Docker использует порт 8000 и отдельный сохраняемый том. При занятом порте:
`$env:ALFA_HTTP_PORT='8003'`, затем та же команда Compose и адрес с портом 8003.
Приложение обслуживается Waitress; обработка анализа идёт в фоне. После перезагрузки
можно продолжить чтение задания. Готовые результаты и отзывы сохраняются между запусками.

Сдача владельцем команды: один GitHub-репозиторий с историей и commit/tag; для private
дать доступ `alfa-hack-2026`. Дедлайн из предоставленных материалов: **26.10.2026 18:00 МСК**.
Команде передавать `alfa_service_integrity_2026-10-24.zip` целиком и соседний файл
`.verification.json` с результатом установки и SHA-256. Веса ONNX требуют Git LFS либо восстановления
закреплённой модели скриптом запуска; инструкция есть в README.
Публикация и отправка в кабинет этим локальным аудитом не выполняются.
